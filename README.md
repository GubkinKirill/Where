# Учёт техники и комплектующих

Веб-приложение для учёта компьютерной техники, комплектующих и одноплатных компьютеров
на небольшом предприятии. Разворачивается внутри локальной сети, в интернет не выставляется.

Масштаб: около 20 компьютеров, 150–300 единиц учёта, до 10 одновременных пользователей.
Приоритет — простота сопровождения, а не масштабируемость.

## Главная идея

**Компьютер и комплектующее — одна и та же сущность.** Системный блок, монитор, планка
памяти, SSD, блок питания, Raspberry Pi — всё это `Item` (единица учёта). Отличаются только
типом и набором атрибутов.

Разница между «компьютером» и «комплектующим» выражается не таблицей, а размещением:
планка памяти внутри системного блока — это комплектующее в его составе; та же планка
на полке шкафа — позиция склада. При перемещении запись не дублируется, меняется размещение.

Размещений шесть видов: внутри другой единицы, на складе, у сотрудника, в кабинете,
передано за пределы отдела, списано.

**Текущее размещение нельзя отредактировать формой.** Оно вычисляется из журнала
перемещений: любое изменение — это новая запись в журнале, единственная точка входа —
сервисная функция `move_item()`. Поле размещения в `Item` — денормализованный кэш,
который обновляет только она.

## Стек

Python 3.11+ · FastAPI · SQLite + SQLAlchemy 2.x · Alembic · Jinja2 + HTMX ·
Pydantic v2 · pytest.

Фронтенд-сборщиков нет: серверный рендеринг плюс HTMX, один статический CSS-файл,
никаких npm-зависимостей. Приложение запускается одной командой без предварительной сборки.

## Состояние работы

Реализация ведётся этапами, после каждого приложение работоспособно.

| # | Этап | Статус |

## Прототип интерфейса

Статические макеты в `prototype/` — карточка единицы, список с фильтрами, форма выдачи.
Бэкенда не требуют:

```bash
cd prototype
python3 -m http.server 8077 --bind 127.0.0.1
```

Затем открыть <http://127.0.0.1:8077/item.html>.

## Установка и запуск

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # и поправить BASE_URL и SECRET_KEY
alembic upgrade head          # создать структуру БД
python -m scripts.seed_demo   # необязательно: демо-данные для знакомства

uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Приложение на <http://localhost:8000>. Сборка фронтенда не нужна: HTMX и CSS лежат
статическими файлами в `app/static`.

Учётные записи демо-набора: `admin / admin12345` (администратор),
`kgubkin / editor12345` (редактор), `viewer / viewer12345` (просмотр).

Боевую учётную запись заводят так:

```bash
python -m scripts.create_admin ivanov --role admin --full-name "Иванов И. И."
```

Тесты:

```bash
pytest
```

## Роли

- `admin` — всё, включая справочники и удаление
- `editor` — вносит перемещения, редактирует карточки
- `viewer` — только просмотр

Проверка учётных данных вынесена в провайдер (`app/auth/providers/`), чтобы позже
добавить LDAP/AD, не переписывая вход.

## Устройство кода

```
app/models      SQLAlchemy: Item, ItemType, Movement, справочники, User
app/schemas     Pydantic: валидация форм и фильтров
app/services    бизнес-логика; move_item() — единственный вход к смене размещения
app/routers     HTTP: разбор формы, вызов сервиса, рендер шаблона
app/templates   Jinja2, весь текст на русском
app/static      один CSS-файл и htmx.min.js
alembic/        миграции
scripts/        создание учётной записи, демо-данные
tests/          сервисный слой и сквозные HTTP-проверки
```

Правило про журнал перемещений держится не на дисциплине: слушатель `before_flush`
в `app/services/location_guard.py` роняет транзакцию, если поля размещения меняются
вне `move_item()`. Создать `Item` в обход сервиса тоже нельзя — первая запись журнала
появляется вместе с единицей.

## Ограничения

- QR-кодов и печати наклеек пока нет — отложено до отдельного решения. Единицы находят
  поиском по инвентарному или прежнему номеру.
- ФИО сотрудников — персональные данные: не логируются и не выводятся в URL.
