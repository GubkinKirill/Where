Раздел для того, кто разворачивает систему и ведёт справочники.

Учётные записи

Раздел «Учётки» в шапке — только у администратора. Там видно, кто может войти, с какой ролью и когда заходил в последний раз.

РольПрава
adminвсё: справочники, шаблоны комплектности, учётные записи, удаление
editorперемещения и карточки единиц, ответы на заявки; справочники только на просмотр
viewerпросмотр списков, карточек и отчётов
employeeтолько личный кабинет: своя техника, коллеги, свои заявки

Учётная запись сотрудника

Роль employee обязательно привязывается к карточке сотрудника: кабинет показывает то, что закреплено за человеком, и без карточки показывать нечего. На одного человека — одна учётная запись, система не даст привязать вторую.

Заводить их всем необязательно: тот, кому запись не завели, по-прежнему смотрит свою технику по табельному номеру на странице «Моя техника». Кабинет — для тех, кому нужно видеть коллег, искать вещи по номеру и писать заявки.

Пароль при создании и сбросе виден в поле открытым текстом — это сделано нарочно, чтобы его можно было продиктовать человеку. Пусть он сменит его в разделе «Профиль»: там смена требует старого пароля, и администратор нового уже не увидит.

Из командной строки на сервере — то же самое, когда войти ещё некому:

python -m scripts.create_admin ivanov --role admin --full-name "Иванов И. И."
python -m scripts.create_admin petrov --role employee --employee 1042

Пароль спросят интерактивно, минимум восемь символов. Той же командой меняется пароль существующей записи; --employee принимает табельный номер.

Если загружали демо-данные, в системе есть записи admin, kgubkin, viewer и petrov с общеизвестными паролями. Перед началом настоящей работы заведите свою и удалите демонстрационные.

Сводка и заявки

Сводка — первая страница после входа для отдела. Плитки кликабельные: каждая ведёт в список с уже наложенным фильтром. Нижний ряд — то, что требует внимания: неподтверждённые выдачи, просроченные возвраты, открытые заявки.

Заявки приходят из личных кабинетов. Редактор ставит статус («в работе», «выполнена», «отклонена») и пишет короткий ответ — сотрудник увидит его у себя. Заявка ничего не перемещает: выдачу по ней оформляют как обычно, в карточке единицы.

Типы единиц

Код типа становится префиксом инвентарного номера, и менять его после того, как номера выданы, не стоит: наклейки на корпусах не переклеятся. Признак «может содержать вложенные единицы» ставится системным блокам, одноплатным компьютерам и комплектам поставки.

В поле «Подсказываемые атрибуты» перечисляются ключи дополнительных полей, по одному в строке: назначение, образ ОС, MAC, IP. Форма будет их подсказывать, но не ограничивать.

Места хранения

Строятся иерархией: «Шкаф 1» → «Полка 2» → «Ячейка A». В списках путь показывается целиком, поэтому названия можно делать короткими. Код (SHELF-02) пригодится позже, когда появятся наклейки с кодами.

Удаление записей справочника

Если на запись кто-то ссылается — например, на кабинет назначены сотрудники, — система откажет в удалении. Это защита истории: удаление разорвало бы связи в журнале. Для вышедшего из употребления снимайте флажок «Используется» вместо удаления.

Установка и запуск

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # поправить BASE_URL и SECRET_KEY
alembic upgrade head          # создать структуру БД
python -m scripts.seed_demo   # необязательно: демо-данные

uvicorn app.main:app --host 0.0.0.0 --port 8000

Ключ --host 0.0.0.0 нужен, чтобы приложение было видно с других машин и с телефонов в той же сети. В .env пропишите BASE_URL — адрес, по которому система доступна.

Обновление версии

git pull
pip install -r requirements.txt
alembic upgrade head

Резервное копирование

Все данные лежат в одном файле SQLite — по умолчанию data/inventory.db. Копировать его нужно средствами самой SQLite, чтобы не поймать копию на середине записи: 

sqlite3 data/inventory.db ".backup 'backups/inventory-$(date +%F).db'"

Проверяйте, что копия открывается и в ней есть данные. Резервная копия, которую ни разу не восстанавливали, — это ещё не резервная копия.

Чего система пока не делает

  • QR-кодов и печати наклеек нет — отложено;
  • единого входа (LDAP, домен) нет: пароли хранятся в самом приложении;
  • фотографий, режима сверки и выгрузки в Excel нет;
  • уведомлений по почте нет и не планируется: почтового сервера у приложения нет.
